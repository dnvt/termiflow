# Visual lesson: scoped BT sibling channels and vertical junction headroom

Status: Watch for BT/LR/RL boundary seams and authored style drift; promoted
visual rule for vertical dual-junction shafts

## Human-eye observations

The fresh H95 packet rendered the complete 237-input corpus in both policy
lanes: 948 rows per lane, including 936 renderable frames and 12 separate
expected-error rows. Both perceptual ledgers now cover 936/936 rows, and both
expected-error policy ledgers cover 12/12 rows. The changed homologs were
reviewed one frame at a time in ASCII and Unicode, default and optimized
modes, in both the canonical requested-style lane and the authored/no-override
lane.

The exact BT sibling scene remains connected and readable, but its first
cross-subgraph route still bends beside the title and the boundary rails read
like one shared trunk. The strict LR/RL sibling chains are wider and the
tightest elbows are gone, yet their cross-group transitions still form
box-like border enclosures. The complex BT subgraph frame retains all labels
and arrows but still has shared-looking boundary rails and title-adjacent
hooks. These remain P2 watches, not golden approvals.

The TD/BT dual-junction frames now show a visible shaft immediately before
each outgoing arrowhead in both styles and both optimization modes. Their
human-eye result is clean and balanced; the independent packet evidence still
reports untraced fallback edges for this precomputed route family, which is a
separate provenance follow-up rather than a visible defect.

The H95 review narrowed the active visual queue. BT parallel-edge homologs
still have a short leftmost source-entry hook; the BT sibling-triple family
still reads as one central rail through titled boundaries; and ASCII LR/RL
subgraph chains still form dense portal-border seams. All labels and endpoints
remain readable in these rows, so these are P2 topology watches rather than
P0/P1 release blockers. The authored lane also exposed a policy issue: several
rows requested ASCII but emitted heavy Unicode contours, which must stay an
independent authored-style contract check rather than being silently merged
with canonical evidence.

The reviewer now ignores elbows whose endpoints are both node-border cells or
both subgraph-border cells. This removes false positives from ordinary bottom
node borders and outer subgraph corners while retaining true title-adjacent
and cross-boundary hooks for human review.

## Hypotheses and falsifiers

1. Exact BT sibling routes need a topology-owned per-edge channel at the
   title and boundary rows. A semantic lane claim without a visibly distinct
   channel is insufficient. Falsify this if a channel reservation leaves the
   shared-trunk impression unchanged or detaches an arrow/title.
2. Strict LR/RL chains need a receiver-owned corridor row, not only extra side
   width. Falsify this if a direction-neutral corridor still encloses borders,
   loses edge identity, or breaks LR/RL symmetry.
3. Mixed BT scenes need a role-aware channel that accounts for internal,
   external, database, and response routes together. Falsify this if the
   channel harms database contours or response arrows.
4. Vertical dual-junction headroom is topology-owned and direction-aware.
   The focused feedback matrix and fresh frames support this rule; falsify it
   with a missing shaft, collapsed arrowhead, overlap, or style/mode drift.

## Rejected experiment

Prioritizing short lane turns ahead of total lane cost in the exact BT
parallel-scene scorer produced a visibly worse upper hook and failed the
parallel-edge goldens. The scorer was returned to cost-first ordering. This
negative result is retained so the self-improving loop does not retry a local
turn heuristic that sacrifices the global rail geometry.

Adding a second quiet row to the exact BT title-entry margin was also rejected:
the scene planner fell back to a generic untraced route and lost the intended
typed topology, so the experiment was reverted. A layout change is not an
improvement when it merely hides the issue behind fallback geometry.
